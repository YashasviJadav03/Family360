# ADR-002: Deterministic Rule Engine vs. ML/LLM Classifier for Welfare Eligibility
- Date: 2026-09-20
- Status: Accepted
- Context: In public welfare delivery, citizen entitlement determinations directly govern access to statutory financial, housing, and educational benefits. We must decide whether to evaluate eligibility via a deterministic rule engine, a statistical machine-learning classifier, or a generative LLM.
- Decision: We implement an auditable, deterministic, rule-based engine for all eligibility evaluations. Machine learning (RapidFuzz/clustering) is reserved exclusively for entity resolution, and LLMs are used exclusively for post-evaluation natural-language explanation.
- Alternatives considered:
  - **Supervised ML Classifier (e.g., Random Forest / XGBoost)**: Rejected because a statistical model predicts probabilities rather than statutory adherence. If an ML classifier predicts a 78% probability of eligibility and denies a widow pension, there is no defensible legal basis, no audit log, and an inherent risk of algorithmic bias against protected social categories.
  - **End-to-End LLM Prompting (Generative AI Eligibility)**: Rejected because LLMs suffer from hallucination, non-determinism, floating-point numeric comparison failures, high latency (1-3 seconds per call), and token costs. A citizen's pension cannot depend on the temperature setting of a generative language model.
  - **Hardcoded Procedural Code per Scheme**: Rejected because hardcoding if-else trees in application logic requires code deployments for every minor government notification change (e.g., income ceiling adjusted from ₹1.5L to ₹2.0L).
- Consequences:
  - *Positive*: 100% auditable and reproducible; zero hallucination; blazing execution speed (<1ms per family); granular pass/fail outputs per rule attribute; dynamic policy updates via database configuration without code releases.
  - *Trade-offs*: Complex multi-condition statutory rules (e.g., composite means-testing) require expressive rule schemas (`attribute`, `operator`, `value`).
